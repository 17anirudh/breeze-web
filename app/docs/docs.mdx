# Breeze

## Overview

**Build Simple. See Every Step. Decide What Comes Next.**
- Breeze is a focused collection of AI engineering skills for developers who want code generated according to their preferences, without adopting an entire automated software development lifecycle.
- It assumes you already have a PRD and a bare project setup. Breeze helps translate that PRD into code through a few deliberate choices, isolated task decomposition, and subagent execution.
- The objective is simple: **generate code that follows sound engineering principles, matches the requested features, and remains understandable to the developer.**

## Workflow

- `/generate` — Start with an existing PRD and bare project setup. Answer a short quiz covering priorities, engineering principles, and additional notes.
- `/divide` — Decompose the PRD into isolated implementation tasks with explicit boundaries and dependencies.
- `/conquer` — Assign tasks to subagents, execute the implementations, and integrate their changes.
- `/examine` — Check wheter the code generated by subagents satisfy the goal defined
- `/improve` - Remove bloated code and comments, making the code concise and runnable without losing code quality
- `/compare` - Compare the generated code with both goals defined and original PRD
- `/prod` - Do basic testing and linting


## The Philosophy

### Architecture

<Architecture />

### Simple Is Okay

- Not every feature needs elaborate architecture, excessive abstractions, or a lengthy planning process. Good engineering means applying the right principles at the right scale.
- Breeze prioritizes simplicity, separation of concerns, readable implementations, and minimal complexity. It compares the implementation against the requested feature and the chosen engineering principles rather than adding sophistication for its own sake.

### Choose Before Generating

- Before implementation, Breeze asks a short quiz to establish the developer's priorities, preferred engineering principles, and additional notes.
- These choices guide code generation. They establish how the implementation should be approached without forcing every developer to follow identical conventions.

### Divide, Then Conquer

- Breeze decomposes the PRD into isolated, well-defined tasks that can be assigned to subagents. Tasks should respect separation of concerns, minimize overlapping changes, and make dependencies explicit.
- Subagents implement their assigned tasks, and the resulting changes are integrated into the project.

### See Every Step

- Breeze logs actions, code changes, and implementation decisions to make the process transparent.
- You should be able to inspect what the AI did and why, rather than blindly accepting generated code.

### Stop at the Right Boundary

- Breeze focuses on code generation and linting. It does not claim to provide comprehensive testing, guarantee bug-free code, or establish production readiness.
- Once the code has been generated and linted, you can inspect the result and decide what comes next.

## What Breeze Optimizes For

- **Simplicity:** Prefer straightforward implementations over unnecessary complexity.
- **Principled code:** Apply relevant engineering principles consistently with the selected preferences.
- **Feature alignment:** Generate code that addresses the requirements in the PRD.
- **Transparency:** Record actions, changes, and implementation decisions.
- **Developer control:** Leave subsequent decisions to the developer instead of enforcing additional workflows.

## Intended Audience

- Breeze is for developers who already understand code and want AI to accelerate implementation without hiding the process or imposing unnecessary ceremony.
- It is deliberately narrow in scope. PRD creation, comprehensive testing, deployment, and operations remain outside its core workflow.
- Generated code can still contain bugs, miss edge cases, or be unsuitable for production. Linting does not establish correctness or security.

## Mental Model

**Bring a PRD. Choose your priorities. Generate the code. See what happened. Decide what comes next.**
